## 4. The payment architecture (feature E — important)

- **Student/parent fee payments** go to the **academy's OWN Razorpay** (mandatory; no platform fallback). `create-payment-order` returns **422** if the academy hasn't configured a gateway.
- **SaaS ₹100 owner subscription** goes to the **PLATFORM Razorpay** (`create-saas-order`). **Two separate money paths — do not conflate.**
- **Confirmation = verify-on-return + webhook backstop.** After the Razorpay sheet closes, the app calls `verify-razorpay-payment` which re-confirms via the Razorpay Payments API and records the payment. The webhook is the async backstop. Both dedup on the unique `payments.razorpay_payment_id`. Client "success" is never trusted alone (invariant #6).
- **Root cause we fixed:** payments were webhook-only with no fallback; a captured ₹100 was silently lost because the webhook never fired.

## 5. Gotchas & known issues (READ before debugging)

1. **DB drift is the recurring theme.** Manual SQL-editor application means objects are often missing. Confirmed-missing-then-fixed this session: `academy_sports` table, the whole `20260627*` layer (`academy_writes_allowed`), `fee_structures.price_per_day`/`days_per_week`. Latent risk: `invoices.total_amount` does **not** exist on this DB (use `amount`/`tax_amount`). **Recommended:** audit applied-vs-folder migrations and build one ordered catch-up script.
2. **Auth emails are flaky.** Supabase Auth SMTP is a personal Gmail (`hammadalipbt18@gmail.com`) — the dashboard itself warns it's not for transactional mail. Signup/invite/reset emails intermittently don't deliver. Fix: move Auth SMTP to a transactional provider (Resend/SendGrid/SES). The Gmail creds in `.env` only feed edge-function emails, **not** Supabase Auth.
3. **Invite links die if previewed.** Supabase invite/magic links are single-use; pasting into **WhatsApp** (or any link-preview crawler) consumes the token before the human taps it. Open the link **directly from the email** on the device with the app installed.
4. **Razorpay webhook must be configured in TEST mode** for test payments, pointing at the per-academy URL `…/razorpay-webhook?academy=<id>` with the academy's webhook secret. (verify-on-return makes this less critical once the new APK ships.)
5. **Low-memory device** kills the app between launches → invite links always cold-start (hence fix D).
