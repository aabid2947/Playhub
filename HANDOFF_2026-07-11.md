## 4. What changed, by area

**Creation-chain enforced at the DB (was UI-only).** Every record is now fully scoped:
coach → center; batch → center + sport + coach; student → center; center_admin/head_coach login →
center. `NOT NULL` + a `users` CHECK + `RESTRICT` FKs (deleting a referenced center/sport/coach is
now blocked — reassign first). **"Coach needs ≥1 sport" stays UI-only** (join-table cardinality
can't be a column constraint). CSV importers updated to supply center (+ sports for coaches).

**Invite / provisioning model reworked** (see §5). Generic Team-invite is now **staff-only**;
coach/parent/student are **record-backed** invites from the record's own profile. head_coach invite
now **mints a coach record** with the chosen sports (so they own a sport); head_coach can now also
**invite parent/student logins**.

**Free-trial caps → upgrade prompt.** Hitting any quota (sports/coaches/students/batches/staff)
opens a shared, **role-aware** `showUpgradePrompt` dialog (owner → "View plans" → SubscriptionPage;
others → "ask your owner") instead of dead-end snackbars. Importers show a cap warning up-front.

**Code review (max effort, 11 findings): 10 fixed + 1 documented.** Highlights: fixed the
lead→student conversion regression (from the students.center_id NOT NULL), hardened the head_coach
invite (rollback on failure, no orphan/double-mint, coach-cap precheck), fixed a batch-form dropdown
crash + hardened the shared `SportPicker`/center dropdowns against stale values, made
create-blocked errors distinguish a frozen subscription from center-scope, and added the
invite-user server guard. #11 (a scoped `DELETE` under `session_replication_role=replica` skips FK
cascades) is documented as moot (DB was wiped) — see the change-log gotcha.

## 5. Invite / provisioning model — current truth

**One shared widget** (`InviteUserSheet`), two modes: **generic role-picker** (Team page) and
**preset** (locked role, launched from a record's profile — links the login to that row).

- **Staff (login-only roles):** invited from the **Team page** generic dropdown — `academy_admin`,
  `center_admin`, `head_coach`, `trainer`. (`head_coach`'s invite **mints a coach record** so it
  owns sports; `trainer`/admins are pure logins.)
- **Coach / parent / student are record-backed** — hidden from the generic dropdown
  (`_recordBackedTargets`), invited from the record's own profile so the login links to a real row:
  - **Coach** → Coaches tab → a coach's profile → "invite login" (`linkCoachId`).
  - **Student / parent** → Students tab → a student's profile → "Logins & access" cards
    (`linkStudentLoginId` / `linkToStudentId`), or the New-student form's login toggle.

**Who can invite what** (`capabilities.invitableRoles` ↔ `can_provision_role`, kept in sync):

| Target | From | Owner | Academy admin | Center admin | Head coach | Coach |
|---|---|---|---|---|---|---|
| Coach | coach profile | ✅ | ✅ | ✅ | ✅ | ❌ |
| Student | student profile | ✅ | ✅ | ✅ | ✅ *(new this session)* | ❌ |
| Parent | student profile | ✅ | ✅ | ✅ | ✅ *(new this session)* | ❌ |
| Staff (admin/center_admin/head_coach/trainer) | Team invite | ✅ | below own rank | head_coach/trainer | trainer only | trainer only |

**Pattern (uniform):** staff create the **record** first (New Coach / New Student — rich forms) →
invite a **login** → the recipient accepts + logs in → the login **binds** to the existing record
(`coaches.user_id` / `students.user_id` / `parent_links`). head_coach is the same, just that its
coach record is minted from the invite sheet. **No dangling logins.**

## 6. How to test the owner flow from scratch (DB is wiped)

1. **Sign up** as a new owner → you land on **SetupAcademyPage** (can't do anything else until the
   academy exists — verified: sport/batch/invite are all blocked with no academy).
2. **Create the academy** (trial or subscribe) → the management shell appears.
3. Create in order: **Center → enable a Sport (at the center) → Coach** (requires center + ≥1 sport)
   → **Batch** (requires center + sport + coach) → **Student** (requires center).
4. **Invite logins:** staff from Team; a coach's login from the coach's profile; a parent/student
   login from the student's profile. Accept the magic link → confirm the login binds (coach appears
   linked; student/parent shown on the student).
5. **Trial caps:** on a free trial, exceeding a cap (1 sport / 2 coaches / 2 batches / 5 students /
   1 each staff role) opens the upgrade prompt; bulk import shows the cap up-front.
6. Log in as **super_admin** (`superadmin@playhubdemo.in`, demo password in `DEMO_CREDENTIALS.md`)
   to inspect academies/relations.

## 7. Known residuals / gaps (not blocking)

- **Coach ≥1 sport** is UI-enforced only (can't be a DB constraint — separate join-table insert).
- **Update/edit** provider errors still say "own center" when a frozen subscription is the cause
  (only the **create** paths were made freeze-aware; same-class, easy to extend).
- **Bulk import on a trial** only imports up to the cap; excess rows fail (now warned up-front, but
  the per-row failure message is still generic).
- A raw-API head_coach invite **without** a coach record still yields a sportless head_coach (the
  mint happens in the mobile invite sheet, not the edge fn).
