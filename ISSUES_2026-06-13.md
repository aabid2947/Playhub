## 5. Inventory stock quantity bug — shows "0 20"

> "He is taking zero after entering, then showing the amount. He should take the unit number
> given in the amount." — voice 7:14:35

In [IMG-20260613-WA0007.jpg](Errors/IMG-20260613-WA0007.jpg) several rows read
**"0 20, piece"** / **"0 20 piece"** (e.g. *tst*, *shirt Football Age 10 Size 15*,
*FOOTBALL U8 SIZE13*). The red-circled correct example is "**30 piece**".

**✅ Root cause (2026-06-14):** not a display bug — the item **create form had no
opening-stock field**, so every new item was saved with `on_hand = 0` (the `0`), while the
`20` was its reorder threshold. Seeded items showed correct stock; only user-created ones read
"0 …". `on_hand` is ledger-driven (the `sync_item_on_hand` trigger on `inventory_movements`),
so the fix adds an **Opening stock** field to the create form
([inventory_item_form_page.dart](apps/mobile/lib/features/inventory/presentation/inventory_item_form_page.dart))
that records an opening `in` movement after insert — no schema change. (On `main` the list also
appended a `Reorder ≥ {n}` segment, which compounded the confusion; the current branch already
shows just `qty · unit`.)

## 6. Inventory — sale entry not saved

> "Purchase entry works… we upload the inventory, but the **sale entry is not being saved**." — voice 7:19:06
> Chat 7:16/7:24: "Purchase entry or Sale is not there."

**✅ Resolved 2026-06-14 — not a save bug.** The `out` (sale) insert path is functionally
identical to `in` (purchase): same RLS (`inv_moves_staff_insert`), same triggers; `recordMovement`
correctly negates the qty so it passes the `out` validate check. There was no code path where a
sale fails to save while a purchase succeeds. The real problem was **recognition** — the app had
no entry *labelled* "Sale" (selling = the generic "Out" movement), so staff couldn't find it.
Fix (UX, no schema change): movement kinds now read **Purchase / Sale / Return / Adjust** with a
one-line hint per kind, the item FAB is "Purchase / Sale", and the ledger badges use the same
labels — single source of truth `kInventoryKindLabels`
([inventory.dart](apps/mobile/lib/features/inventory/data/inventory.dart)).

## 7. Inventory — Issue / Return transfers

> Chat 7:18: "Issue or Return. From **HO to Center**, **Center to Center**, and **Center to HO**."

Stock movement/transfer feature with three flows (HO → Center, Center → Center, Center → HO).

**✅ Implemented 2026-06-14 — per-location stock model.** New `inventory_stock(item_id, center_id,
on_hand)` table (center_id null = HO) tracks balances per location; `inventory_movements` gained
`center_id` + `to_center_id` + a `transfer` kind. A transfer is one movement (qty > 0) — the sync
trigger subtracts from the source balance and adds to the destination, leaving the item total
unchanged; purchase/sale/return/adjust post to the chosen location. `inventory_items.on_hand`
stays the academy-wide total. Migration
[20260614000100](supabase/migrations/20260614000100_inventory_per_location_stock.sql); pgTAP
[rls_inventory_stock.sql](supabase/tests/rls_inventory_stock.sql). Mobile: the movement sheet has
a **Transfer** type with From/To location pickers (+ a Location picker for the other types), and the
item page shows a **Stock by location** breakdown with transfer direction in the ledger.
**Owed:** web-admin `npm run gen:types` (new table + columns). **Follow-up:** tighten which staff
may transfer to/from which location (currently any academy staff; the HO null-center case needs
care) — see CLAUDE.md change log.
